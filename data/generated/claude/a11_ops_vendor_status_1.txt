<<<ITEM kind=vendor_status lang=en hard_negative=false topic=API doc idempotency>>>
Idempotency (API reference excerpt)

To safely retry requests, send an Idempotency-Key header with a unique value (UUID v4 recommended) on POST requests. Keys are stored for 24 hours. If a request with the same key and a different body is received, the API returns HTTP 409 with error code idempotency_key_reuse. Responses to successful replays include the header Idempotent-Replayed: true.
<<<END>>>

<<<ITEM kind=vendor_status lang=en hard_negative=false topic=refund API documentation>>>
Refunds (API reference excerpt)

POST /v2/refunds creates a refund against a captured payment. The amount can be lower than or equal to the remaining refundable amount; multiple partial refunds are allowed. Refunds to card normally take 5-10 business days to appear on the cardholder's statement. The refund object has status pending, succeeded or failed; failed refunds trigger the refund.failed webhook.

<<<ITEM kind=vendor_status lang=en hard_negative=false topic=payout API docs>>>
Payouts (API reference excerpt)

POST /v1/payouts initiates a transfer to a verified bank account. Required fields: amount (minor units), currency, destination. The response contains status queued, and the payout moves to in_transit when submitted to the bank. Possible failure reasons include invalid_account, closed_account and sanctions_hold. The cut-off time for same-day processing is 14:30 UTC.

<<<ITEM kind=vendor_status lang=en hard_negative=false topic=webhook signature docs>>>
Verifying webhook signatures (documentation excerpt)

Each webhook request includes the header X-Signature with a timestamp and an HMAC-SHA256 hash of the timestamp and the raw body, using your endpoint secret. Compute the hash over the raw bytes, not parsed JSON, and compare in constant time. Reject events with timestamps older than five minutes to prevent replay. Rotate secrets from the dashboard; both secrets are valid for 24 hours.
<<<END>>>
