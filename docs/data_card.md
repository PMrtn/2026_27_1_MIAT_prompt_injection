# Data card: self-generated prompt-injection detector dataset

## Purpose

Binary classification of **tool outputs** (the text an MCP tool returns to an LLM agent): `label = 1` if the text
contains an injected instruction aimed at the agent (indirect prompt injection), `0` otherwise. The dataset trains
and evaluates the ML defense layer. It is not used to run the end-to-end agent experiment.

## How it was made

Everything is generated by code in `src/pidefense/data/`. Running `python -m pidefense.data.build` again rebuilds
the dataset without API calls, because the LLM responses are cached in `data/generated/llm_cache.jsonl`.

| Component | Source | Size |
| --- | --- | --- |
| Benign free-text carriers | `gpt-5.6-luna`, 10 texts per call: emails, web pages, documents, product reviews, support tickets, calendar invites, news. ~40 topics × 8 tones × EN/HU, generated natively in Hungarian (not translated) | 2,358 texts |
| Hard negatives | `gpt-5.6-luna`: benign text that reads like instructions (how-tos, IT runbooks, request emails, recipes, policies, AI-assistant product docs, security awareness, meeting action items) | 1,171 texts |
| Structured carriers | Faker (`en_US`/`hu_HU`): transaction lists, calendar events, orders (JSON), search results, contact cards. Each has one attacker-controllable field | 1,500 |
| Attack templates | Hand-written: 8 families × EN/HU, 10–14 templates each (`templates.py`) | 192 templates |
| Attacker goals | Hand-written: 24 EN + 24 HU goal phrasings. Slot values (emails, IBANs, URLs, files, products, people) are random Faker values | — |

Cost of LLM generation: **$0.57** (360 calls, `reasoning_effort="none"`). Every call is listed in
`results/llm_cost_ledger.csv`.

**Injection.** A payload is inserted into a carrier at the start, middle (paragraph/sentence boundary) or end.
It is wrapped plain (50%), as an HTML comment, as a markdown quote, as a signature block or as a hidden `<span>`.
For structured carriers the payload is appended to the attacker-controlled JSON/text field. In 10% of samples
the payload language differs from the carrier language. A small share of bare payloads ("standalone") is balanced
by the same number of short benign snippets, so that text length is not a shortcut.

## Attack families

| Family | Description | Splits |
| --- | --- | --- |
| S1 | direct override ("ignore previous instructions …") | train / val / test |
| S2 | fake system / authority message | train / val / test |
| S3 | role-play / persona hijack | train / val / test |
| S4 | urgent "message from the user" social engineering | train / val / test |
| S5 | appended task ("after you finish, also …") | train / val / test |
| U1 | boundary spoofing (fake end of output, fake user turn, fake tool-call JSON) | **test only** |
| U2 | obfuscation (base64, leetspeak, zero-width, homoglyphs, spacing, reversal, ROT13, payload splitting) | **test only** |
| U3 | implicit "note to AI assistants" phrasing without trigger words | **test only** |

## Splits and leakage controls

- **Carriers** are split 70/15/15 by a hash of their id. All samples built from a carrier (benign, injected,
  snippet) share its split.
- **Seen-family templates** are split 70/15/15 within each (family, language), with at least one template each in
  val and test. An injected sample only uses templates from its own split's pool.
- **Unseen families** U1–U3 appear only in the test split.
- **End-to-end canaries** (`attacker@evil.example`, the attacker IBAN, the phishing URL, `MX-7731`) never appear;
  the build fails or drops the sample if one does. The end-to-end experiment uses only test-pool templates and
  unseen families with these canaries.
- **Length:** every sample is at most 256 model tokens, so training-time truncation never cuts off a payload. Free
  text carriers are trimmed at word level; 325 over-long structured samples were dropped.
- **Duplicates:** exact duplicates after whitespace/case normalisation were dropped (55).

## External sanity check (evaluation only)

`deepset/prompt-injections` (Hugging Face, Apache-2.0, 662 short EN/DE prompts) is downloaded by
`python -m pidefense.data.external`. It is used once to score the trained detector, never for training or threshold
selection. It is a different distribution: direct user prompts rather than tool outputs, and partly German.

## Known limitations

- Labels come from construction, not human annotation. Only a small manual spot check of random samples (several
  families, both languages) was done. It found no label errors, but it is not a systematic audit.
- The same model family (`gpt-5.6-luna`) generated the carriers and later acts as the agent. Carrier style is
  therefore homogeneous, and the detector may partly learn generator artefacts; the external check probes this.
- Attack templates were written by one author. Seen and unseen families come from the same author, so "unseen"
  means unseen *attack strategy*, not unseen *author style*.
- Hungarian text for the carriers is LLM-generated; Hungarian templates were written by the author.
